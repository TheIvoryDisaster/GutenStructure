# Release promotion

The permanent [branch policy](branch-policy.md) applies to all organization repos, including Husbandry: beta requires PR+CI with super-maintainers review-only bypass; main/release require PR+CI and one independent super-maintainers approval, which the owner's `release-debugger` team may bypass through a PR. Ordinary branches remain unprotected. CODEOWNERS is ownership documentation, not an additional approval gate. No custom App or GitHub Actions review bypass is needed.

Promote tested work beta → main → release through PRs. Keep MeitouClient master as its upstream mirror and fork as its development branch. Do not rename existing branches just to apply policy. Missing branches/workflows need reviewed bootstrap commits. A passing engine-free CI run does not replace licensed-data/in-game testing or prove a complete production package.

Production workflows use reviewed SHA-pinned central release-gate/package helpers. Tags point at the exact current protected release head; the gate validates that head and enforced native team review with no release bypass. GitHub may hide bypass actors from the build token, so the gate's hidden-list case relies on the scoped administrator's read-back/reconciliation. Changing rules does not change historical immutable caller pins. Promote central helpers to GutenStructure release, then update callers together through PRs. Do not publish incomplete artifacts or licensed game assets.

To install/repair rules, preview then apply **Configure release branch protections** on main, target organization, environment Default. The Meitou-owned token needs All repositories, Administration read/write and Members read. Reconciliation discovers public repos hourly; templates do not copy GitHub settings. See [onboarding skill](../.agents/skills/onboard-repository/SKILL.md) and [policy details](branch-policy.md). Personal GutenStructure administration uses its separate credential and PR+CI/zero-reviewer exception.

Avoid Update branch on a permanent release-source PR that would pull development into production. Use a temporary promotion/backport branch when combining histories is necessary. A history-only merge commit does not require a reverse merge just to align GitHub counters.
